# 原生安卓本地阅读器
## 项目 PRD · v0.2

**文档状态：评审草案（已回写 UI 设计稿 v1 的确认结论）**  
**编制日期：2026-09-24　修订日期：2026-10-04**  
**适用对象：产品、交互设计、Android 开发、测试**  
**项目名称：本地阅读器（暂名，正式名称待定）**

> 将本地图书、稍后阅读与 RSS 文章收拢到一个原生 Android 应用中，以接近 Readest 的图书排版和可靠的本地保存，形成“收集—整理—阅读—继续阅读”的完整闭环。

本文把用户已提出的要求作为产品约束，把新增的默认值、优先级、技术路线与验收阈值标为方案建议。本文不是技术实现完成声明；开源项目能力不等于本项目已经具备相同能力。所有性能和成功率数字均为拟定验收目标，须在技术验证后冻结。

### 1.2 当前执行假设，不等于用户已经确认

**原生的定义。** 本文暂按 Kotlin/Jetpack Compose 实现书架、列表、设置和系统交互，允许正文使用嵌入式 WebView 排版。若要求正文也完全不使用 WebView，必须在正式开发前重新评估阅读内核、MOBI 兼容与成本，不应在开发中后期再改变。

**本地优先。** 首版无账号、无强制云服务、无自建服务端依赖；已保存内容断网可读。RSS 更新和网页获取需要网络，但阅读已完成保存的内容不依赖网络。云同步不纳入首版。

**终端与发布。** Android 手机、平板与折叠屏均为首版正式支持的终端（v0.2 由用户确认，原“兼顾基础平板布局”的表述作废），布局规则见 4.5；建议最低 Android 10，最终由依赖和真机验证决定。界面首版为简体中文。正式应用名、商业模式、整体开源协议和发布渠道尚未确定。

**兼容承诺。** 首版支持无 DRM 的目标图书，以及用户正常有权访问的目标网页；不以绕过付费、验证码、登录限制或内容保护为功能前提。

### 1.3 产品目标与非目标

产品目标是让用户在同一应用中管理三类内容，获得稳定的离线阅读、明确的保存状态、连续的阅读进度，以及可备份的数据。优先级顺序为：内容与数据正确性 → 排版与阅读连续性 → 保存成功率 → 管理效率 → 扩展能力。

首版不做在线书城、盗版书源聚合、公众号账号抓取订阅、知乎推荐信息流、漫画在线源、社交评论、AI 总结、翻译、TTS、跨端云同步、PDF OCR 或专业 PDF 编辑。用户提供合法文件与可访问链接，是本产品的内容入口；“支持公众号文章链接”不代表“支持订阅任意公众号”。

## 02 目标用户、场景与成功标准

### 2.1 目标用户与任务

主要面向同时阅读本地电子书、网页长文和新闻订阅的个人用户。其核心需求不是获得更多推荐，而是把已选择的内容保存下来，按自己的节奏阅读。

| 场景 | 用户任务 | 期望结果 |
| --- | --- | --- |
| 本地图书整理 | 一次导入多本不同格式图书，按分类存放 | 无重复书目、无原文件误删；随时继续阅读 |
| 通勤与弱网阅读 | 断网阅读前一天保存的书和文章 | 正文与已承诺保存的图片均可显示 |
| 碎片收集、集中阅读 | 从知乎或微信分享文章，稍后统一阅读 | 保存动作轻量，正文排版统一，失败原因可见 |
| 新闻订阅 | 添加机构官方 RSS，定期查看新文章 | 知道来源、更新时间、全文/摘要与离线状态 |
| 图文和漫画阅读 | 打开扫描 PDF、漫画包和长图 | 保留原页/原图，缩放和翻页稳定 |
| 更换设备或重装 | 导出备份并恢复 | 图书、文章、订阅、进度等按备份范围恢复 |

### 2.2 核心产品原则

**内容统一管理，不强行统一渲染。** 书籍和文章共享阅读偏好、状态和搜索入口；流式正文、PDF 和漫画允许使用不同引擎。RSS 条目不会自动变成书架上的一本书。

**保存状态必须真实。** 有链接不等于有正文；有正文不等于全文；有文字不等于图片已离线。列表和详情必须表达这种差异。

**操作不破坏已有成果。** 重新抓取失败不得覆盖已有快照；清理缓存不得删除用户主动保存的内容；换字体不得丢失阅读位置。

### 2.3 版本成功标准

| 维度 | 建议发布目标 | 说明 |
| --- | --- | --- |
| 核心闭环 | 所有 P0 核心流程与阻断性异常用例通过 | 不以“平均成功率”掩盖数据丢失、错书或安全问题 |
| 本地格式 | 第 16 章标准样本各格式成功打开率 ≥95% | 被判定成功的样本不得存在关键正文缺失；失败需明确反馈 |
| 网页保存 | 合格公开样本的完整图文保存率，各站点类型 ≥90% | 分开统计公众号、知乎专栏、知乎回答；不外推全站成功率 |
| 离线承诺 | 标为完整图文离线的验收样本，断网验证通过率 100% | 只对本文定义的正文及必要图片，不包括视频和交互内容 |
| 进度与备份 | 关键定位用例、备份恢复一致性通过率 100% | 包含进程结束、重启、旋转、换字体和多入口阅读 |

以上是产品验收目标，不是对当前开源软件或未来线上表现的测量结论。真实网站会变化，必须记录测试日期、设备、页面类型和样本分母。

## 03 版本范围与优先级

### 3.1 版本定义

**R0：技术验证。** 只验证排版内核、站点保存和大文件阅读等风险，不以功能数量验收。输出原型、样本结果、依赖许可证清单和技术决策。

**R1：首个完整可用版本。** 覆盖书架、五类本地内容、稍后阅读、官方 RSS 和基础备份。EPUB、MOBI、TXT、PDF、基础漫画均为首版范围，不因开发难度默认取消某一类。

**R1.1：增强版本。** 增加进阶格式、标注、搜索与个性化能力；必须在 R1 稳定后进入。本文 P0 对应 R1 必须满足，P1 对应后续增强，P2 为远期候选。

### 3.2 范围清单

| 模块 | P0：R1 必须具备 | P1 / P2：不阻断 R1 |
| --- | --- | --- |
| 书架 | 文件/批量导入、分类、排序、标题/作者搜索、去重、删除 | 目录监听、复杂标签、跨库全文搜索 |
| 流式图书 | EPUB、MOBI、TXT；目录、分页/滚动、字体版式、进度、书签 | 高亮笔记、词典、阅读统计、TTS |
| 固定页面 | EPUB 固定版式基础显示；PDF 原页、缩放、页码、书签 | PDF 文本搜索/选取、密码 PDF、裁边、手写 |
| 漫画 | CBZ/ZIP、图片文件夹；JPG/PNG/WebP；左右/上下阅读 | CBR/RAR、双页拼接、高级裁边；在线漫画源不做 |
| 稍后阅读 | 分享/粘贴链接、正文与图片保存、指定站点适配、归档/收藏 | 批量链接、文章 EPUB 导出、复杂筛选 |
| RSS | RSS/Atom、分组、OPML、手动/后台刷新、全文保存策略 | 第三方 RSS 账号同步、通知、组件 |
| 数据与设置 | 本地持久化、存储管理、手动备份/恢复、隐私控制 | 自动备份、WebDAV、多设备同步 |

### 3.3 格式边界

| 类型 | 首版明确支持 | 首版不承诺 |
| --- | --- | --- |
| EPUB | 常规 EPUB 2/3 流式书籍；固定版式保留页面 | 脚本交互 EPUB、复杂音视频和所有厂商私有扩展 |
| MOBI | 无 DRM 的旧 MOBI；混合 MOBI 的可识别正文 | DRM、KFX；独立 AZW3 文件列为增强项 |
| TXT | UTF-8、UTF-16、GB18030 等常用编码，可手动纠正 | 凭任意字节流百分之百识别编码 |
| PDF | 未加密的文字/扫描 PDF 原页显示 | 自动重排为图书、OCR、表单与密码文件 |
| 漫画 | 单个 CBZ/ZIP 作为一册；用户选中的图片目录作为一册 | 任何压缩包都能识别为漫画；RAR/CBR 首版不支持 |

“支持某格式”必须包含导入、打开、显示、导航和位置恢复；只提取出纯文本不算支持 PDF 原页阅读。依赖宣称的格式能力仍需本项目样本验证。

## 04 信息架构与页面职责

### 4.1 主导航

底部导航设为“书架 / 稍后阅读 / RSS / 设置”。阅读器为独立全屏页面，不作为第五个常驻标签。默认进入上次访问的主栏目；首次启动进入书架，不自动联网、不弹账号注册。

导航采用悬浮胶囊样式：四个栏目位于一枚毛玻璃胶囊内，选中项以浅色药丸底并改用实心图标；胶囊右侧为独立的圆形“+”按钮，按栏目执行主操作——书架为“导入图书”，稍后阅读为“粘贴链接”，RSS 为“添加订阅”，设置页不显示该按钮。导航悬浮于内容之上，内容底部留出渐隐区域，不遮挡最后一行可操作内容。

| 页面编号 | 页面 | 核心内容与操作 |
| --- | --- | --- |
| UI-01 | 书架 | 最近阅读、封面列表/网格、分类、搜索、导入与批量操作 |
| UI-02 | 图书详情 | 文件格式、大小、作者、导入时间、进度、分类、删除 |
| UI-03 | 流式阅读器 | 正文、目录/书签、进度、字体与版式、阅读模式 |
| UI-04 | PDF/漫画阅读器 | 原页/原图、页码、缩略图、缩放、方向、书签 |
| UI-05 | 稍后阅读 | 未归档/已归档、收藏筛选、阅读状态、保存状态 |
| UI-06 | 保存预览/任务详情 | 链接、标题、正文预览、图片进度、登录或重试入口 |
| UI-07 | 文章阅读器 | 标题、作者、来源、时间、正文、归档、原文、保存状态 |
| UI-08 | RSS 列表/源管理 | 全部未读、按源/分组筛选、刷新、添加、OPML |
| UI-09 | 订阅源详情 | 源地址、更新时间、保存策略、错误、暂停/删除 |
| UI-10 | 设置与数据管理 | 主题、阅读默认值、存储、备份恢复、网站会话、关于 |

### 4.2 关键交互约束

书架默认按最近阅读降序，排序方式为“最近阅读 / 书名 / 作者”三种；稍后阅读默认按保存时间降序；RSS 默认按发布时间降序，缺失时间时使用首次发现时间，并标注“发布时间未知”。发布时间、抓取时间和最近更新时间必须分别保存。

图书卡片展示封面、标题、作者和进度；文章卡片展示标题、来源、时间、阅读状态及离线状态。错误状态不能只靠颜色区分。工具栏使用文字或无障碍标签解释图标含义。

阅读时单击中部切换工具栏；点击超链接、脚注、图片和长按选词时，不同时触发翻页。Android 返回先关闭弹层，再返回上级，并保留原列表的滚动位置和筛选条件。

### 4.3 搜索与空状态

P0 提供书架标题/作者搜索，以及文章标题/作者/来源搜索；跨正文全文搜索为 P1，不展示一个实际不工作的“全文”入口。中文按包含匹配，拉丁字母不区分大小写；搜索结果标明内容类型和入口。

空书架展示“导入图书”；空稍后阅读展示“粘贴链接”和分享说明；空 RSS 展示“添加订阅”和“导入 OPML”。无搜索结果、没有未读、网络失败和从未添加内容必须使用不同文案。

以下约定来自已评审的设计稿，开发与测试以此为准；具体数值见设计稿中的“UI 规范”画板。

| 编号 | 约定 | 说明 |
| --- | --- | --- |
| UX-01 | 整体风格参考微信读书 | 浅灰白底、柔和圆角卡片；界面文字用思源黑体，正文与书名用思源宋体；字重最高 500，不使用粗体 |

| UX-07 | 工具栏状态 | 顶部同一位置改为“本章剩余 x 页”（字号、样式与书名一致），右侧为“添加书签”和“关闭本书”圆形按钮，不加背景条；底部页码区域换成“目录 / 书签 / 阅读 / 设置 / 搜索”五项导航胶囊 |
| UX-08 | 阅读面板分工 | “阅读”面板含亮度、背景、翻页方式、夜间；“设置”面板含字号、字体、行距、边距、原书样式。所有控件统一为“左侧标签 + 右侧分段控件”行样式 |
| UX-09 | 目录、书签、书内搜索 | 手机上使用全屏卡片（自状态栏下方升起）；目录按原书层级缩进，已读篇目弱化，当前篇目整行高亮并标注“剩 x 页”，每项右侧显示页码（随排版变化）；搜索结果按章节分组、当前章节优先 |
| UX-10 | 删除确认、继续阅读菜单等 | 维持设计稿当前的底部操作表与浮层菜单样式 |
| UX-11 | 状态表达 | 保存状态一律“图标 + 文字”，文案以 11.2 为准，书架、稍后阅读、RSS、文章页一致 |
| UX-12 | 触控与对比度 | 最小触控热区 48dp（视觉可小于热区）；小字对比度不低于 4.5:1 |

## 05 本地书架与文件导入

### 5.1 标准导入流程

入口为书架“导入”、系统文件“用此应用打开”和系统分享文件。流程为：选择文件 → 校验可读性与类型 → 复制到暂存区 → 识别元信息与计算内容指纹 → 去重 → 正式入库 → 提示成功/失败 → 打开或继续导入。

默认采用“复制入库”，导入完成后原文件被移动或删除不影响阅读。原文件始终不由本应用主动删除。Android 文件选择采用系统 Storage Access Framework，以用户选择的文件或目录为边界，而非要求全盘访问。[S10]

### 5.2 功能需求

| 需求编号 | 规则 | 验收要点 |
| --- | --- | --- |

### 5.3 特殊规则与异常

导入前检查剩余空间；空间不足时明确显示“所需空间/可用空间”，不删除现有内容腾挪。暂存空间估算必须包含复制、解包和解析开销。取消导入只清理本次未完成的临时数据。

识别加密/受保护文件时提示“此文件受保护或需要密码，当前版本不支持”；损坏文件提示“文件无法解析，可重新选择文件”；用户取消选择不产生错误弹窗。外部来源的临时读取授权失效时要求重新选择，不能反复无提示重试。

分类以用户自建为主。EPUB 元数据中的主题字段（dc:subject）质量参差，不自动生成分类；是否用它做“建议分类”待定（D-10）。

漫画目录首版不递归扫描任意层级：当前选中目录内图片为一册，子目录不自动合并。书架显示标题和来源目录名，避免把多册混成一本。

## 06 图书阅读与 Readest 排版对齐

### 6.1 阅读器共性

流式阅读器覆盖 EPUB、MOBI、经分章处理的 TXT，以及清洗后的网页/RSS 文章。底层可以不同，但同类设置名称、交互和默认主题应一致。EPUB 固定版式进入固定页面模式，不强制套用字号重排。

Readest 的项目文档列出分页/滚动、字体版式设置、书库和网页剪藏能力；本文以这些体验作为参考，不要求复制其全部功能和界面。[S1]

| READ-02 · P0 | 目录按原书层级展示；点击定位；无目录明确提示 | 不伪造章节；返回正文后定位准确 |

| READ-09 · P1 | 高亮、笔记和书内搜索 | 复用内容锚点；不作为 R1 的隐藏依赖 |

### 6.3 Readest 对齐的验收维度

**排版完整。** 不丢段、重段或裁切正文；保留标题层级、粗斜体、引用、列表、图片说明、表格与代码。长表格/代码允许独立横向查看，不让整篇正文横向溢出。

**中文阅读。** 常用中文标点不得明显孤立在行首；中英混排、数字和链接有合理断行；中文字体回退不出现大片缺字。竖排、注音等复杂排版仅对纳入样本的能力承诺，不默认全覆盖。

**分页稳定。** 改字号、改边距、旋转、打开脚注、应用切后台后回到同一阅读位置。图片加载与字体加载完成后，不发生无法恢复的跳页。

**样式可控。** 提供“保留原书样式”和“自定义阅读样式”。前者优先保留出版社排版，但必要的视口与安全修正仍生效；后者仅覆盖可读性相关样式，不把标题、表格、代码全部格式化成正文。

**视觉比较。** 同一设备、同一图书、可对齐的字体与字号，与固定版本 Readest 对照。比较层级、留白、图文关系、翻页及定位；不要求像素级复制，也不把“同内核”作为验收通过依据。

### 6.4 建议默认值与 TXT 处理

初始建议为书籍分页、文章滚动；正文 18sp 等效字号、行高 1.7、段间距 0.5em、横向边距 20dp、纵向安全区之外边距 16dp。字号提供 12–36sp 等效范围；具体值须经真机和字体缩放测试后冻结。Web 正文的 CSS 单位需由适配层映射，不直接把 CSS px 当作 Android sp。

TXT 先识别编码，再建立稳定的段落和章节索引。支持用户手动选择编码并重新解析；使用可预览的章节规则，识别失败时允许按固定大小分段，不把整本大文件一次性塞入单页。重新分章先提示可能影响书签定位，保留原始文件与原定位备份。

### 7.3 跨格式进度规则

进度至少区分“当前位置”和“历史最远位置”。用户回翻不能因百分比变小被认定为数据丢失；阅读状态也不以最远百分比反复自动变化。书籍读完由用户确认，或到末尾时提示确认；不因拖动进度到结尾直接完成。到达最后一页时，正文末尾显示确认卡片：“标为已读完”（同时移出继续阅读，保留阅读位置）或“暂不标记，继续翻看”。

流式内容保存“章节/资源标识 + 内容锚点 + 段落或文本偏移 + 备用百分比”，不只保存屏幕页码。PDF 保存原始页索引和标准化页内坐标；漫画保存图片标识、逻辑序号和页内偏移。不同格式使用各自的定位载荷，不假定一个 CFI 能覆盖全部内容。

**POS-01 · P0：** 稳定位置变化后防抖落盘，建议不超过 1 秒；退出阅读器或切后台立即提交。进程被终止后最多回退至最近一次已提交位置，不能仅在正常退出时保存。

**POS-02 · P0：** 原始锚点失效时按备用锚点恢复并显示“已恢复至附近位置”；不得静默回到开头。文章重新抓取的版本切换不得直接丢弃旧位置。

## 08 稍后阅读：获取与保存

### 8.1 保存入口与主流程

支持系统分享文本链接、应用内粘贴 URL 和从 RSS 加入稍后阅读。分享文本可能同时包含标题与 URL：先提取链接；包含多个有效链接时展示选择，不在后台擅自全部抓取。不得在应用启动时持续读取剪贴板。

链接保存采用“先记录、后获取”：立即建立可见条目，再异步处理正文。网络断开仍可保存链接并显示“等待联网”；用户无需停留在页面等待完整下载。

### 8.2 功能需求

| 需求编号 | 规则 | 验收要点 |
| --- | --- | --- |
| CLIP-01 · P0 | 先创建条目和任务，再抓取；允许取消、重试 | 保存链接立即可见；重复点击不产生并行重复任务 |
| CLIP-02 · P0 | 识别标题、作者、来源、发布时间、正文；缺失则标明 | 不把网页导航、推荐区或登录提示当正文 |
| CLIP-03 · P0 | 站点规则优先，通用正文提取回退；保留结构化正文 | 标题、段落、引用、列表、代码和表格可阅读 |
| CLIP-04 · P0 | 保存正文必要图片并改写为本地资源地址 | 飞行模式验证；图片失败显示缺图数量和重试 |
| CLIP-05 · P0 | 提供原文链接、抓取时间、保存详情与预览 | 用户能识别过期快照和部分保存 |
| CLIP-06 · P0 | 自动抓取不完整时，可打开应用内交互页面再提取 | 需要登录/验证时必须由用户处理，不无限重试 |
| CLIP-07 · P0 | URL/内容身份判重；重复保存定位既有条目 | 不覆盖已读/归档/收藏；重新获取需明确操作 |
| CLIP-08 · P0 | 新版本正文与资源准备完成后再原子替换 | 新抓取失败保留旧版；不以空正文覆盖有效内容 |

### 8.3 获取管线与内容质量

处理顺序为：URL 校验 → 重定向和站点识别 → 普通网络获取 → 正文提取 → 内容质量检查 → 必要时用户交互获取 → 安全清洗 → 本地资源保存 → 快照提交。

完整性判断应综合正文容器、结构、登录/展开/付费提示、已知截断特征和必要图片，不使用“字数超过某阈值”等单一规则认定全文。自动判断无法确认时显示“完整性未确认”，允许用户预览确认当前正文；同时保留“用户确认”来源，不伪装为系统验证。

通用正文提取不是安全清洗。Mozilla Readability 明确建议额外处理不可信 HTML 的安全问题；本产品需要独立的清洗、资源校验和阅读环境隔离。[S3]

### 8.4 资源保存规则

处理普通图片、懒加载地址和 srcset；选择足够阅读的清晰版本，并记录原图 URL、MIME、尺寸、校验值和下载状态。正文与图片均成功写入后才能更新最终状态。图片下载可独立重试，不必每次重抓整篇文章。

首版不离线下载视频、音频、互动卡片及小程序内容，使用标题/封面/原文入口占位。关键图表缺失按部分保存；不将图片中的文字误当成可复制正文。允许用户明确排除装饰性资源，但必须在保存详情记录排除项。

## 09 站点兼容与文章管理

### 9.1 首版站点支持矩阵

| 页面类型 | P0 目标 | 边界与降级 |
| --- | --- | --- |
| 微信公众号普通图文 | 标题、公众号/作者、时间、正文、正文图片 | 被删除、风控或验证页保留链接；不生成虚假正文 |
| 微信公众号复杂图文 | 保留主要文字、图表、引用与图片顺序 | 不复制全部公众号装饰；视频/音频以占位显示 |
| 知乎专栏文章 | 标题、作者、正文、图片及可保留的公式/代码 | 正文不可访问则提示；复杂公式不支持时标注降级 |
| 知乎单个回答 | 问题标题、回答作者、该回答正文与图片 | 不把同题其他回答或推荐内容混入 |
| 知乎问题页 | 识别为多回答页面，提示选择单个回答链接 | 不承诺自动保存全部回答；批量回答为后续议题 |
| 一般新闻/博客页 | 使用通用提取器尽力保存 | 不作为“所有网站均支持”的承诺 |

网站选择器和抓取策略属于可维护的站点适配模块，不写死在阅读器中。每条站点规则记录适用域名、页面类型、规则版本、回归样本和验证日期。首版规则随应用版本更新，不提供可执行远程脚本下发能力。

### 9.2 登录与会话

本应用内的网页会话与外部浏览器、微信或知乎 App 的登录态不作共享假设。用户在外部已登录，不代表分享后应用能直接获得同样内容。登录必须发生在真实站点的交互页面，不制作模仿网站的账号密码表单。

站点拒绝嵌入式登录或需要外部应用时，提供“打开原文”和“仅保存链接”；外部打开成功不自动被视为应用已经获得正文。用户处理完登录/验证后，主动点击“保存当前正文”再检查完整性。

会话按站点保存，可在设置中清除；Cookie、令牌不进入分析日志、备份包或导出文章。阅读本地快照不得复用带登录权限的抓取页面。

### 9.3 稍后阅读与 RSS 文章共用状态

**ART-01 · P0：** 阅读状态为未读、阅读中、已读；归档和收藏为独立开关。归档不等于删除，收藏不等于已读。同一篇文章经 RSS 与分享进入时，尽量关联同一内容实体和阅读状态。

**ART-02 · P0：** 文章正文出现并有阅读行为后进入阅读中；建议到达正文末尾且有效阅读累计 ≥10 秒自动标为已读。短文可手动标记，跳转到底部不立即完成；最终阈值由交互验证冻结。

**ART-03 · P0：** 从 RSS 加入稍后阅读只增加管理关系，不重新下载和复制资源；自动补全尚未完成的离线资源。移出稍后阅读不删除仍被 RSS 或收藏引用的同一文章。

**ART-04 · P0：** 更新已保存正文前展示“重新获取”意图；如果新旧文本不同，保留旧版本直到用户确认切换。取消更新继续使用旧快照，不修改已读状态。

**ART-05 · P0：** 文章页右上角“更多”菜单包含：标为已读/未读、加入/取消收藏、保存详情（带缺图等摘要）、重新获取全文、复制原文链接、在浏览器中打开、移出稍后阅读（危险操作置底并以红色区分）。

## 10 RSS 订阅与全文阅读

### 10.1 添加订阅与官方来源

支持输入 RSS/Atom 地址或网站地址。直接输入有效 Feed 后预览源名称、站点域名与最近条目；输入网站地址时尝试发现页面声明的订阅链接，找到多个则由用户选择。失败提示“未发现订阅源”，不把普通网页强行转成 RSS。

首版不预置无法核实的“官方源目录”。用户从新闻机构官网获取地址后添加；应用展示源地址和站点地址，但不因二者标题相似就自动标“官方认证”。如后续预置官方源，需记录机构官网声明、验证日期和维护责任人。

### 10.2 功能需求

| 需求编号 | 规则 | 验收要点 |
| --- | --- | --- |
| RSS-01 · P0 | RSS/Atom 解析、重复订阅识别、标题编辑与分组 | 同源不重复添加；嵌套 OPML 分组导入结果可预览 |
| RSS-02 · P0 | 手动刷新、下拉刷新、单源刷新和后台定期刷新 | 一个源失败不阻断其他源；显示实际最后成功时间 |
| RSS-03 · P0 | 自动区分 Feed 内正文、摘要与外部原文链接 | 摘要明确标识；不能冒充本地全文 |
| RSS-04 · P0 | 摘要条目按策略获取原文，与稍后阅读共用文章管线 | 同样经过提取、完整性判断、图片保存和安全清洗 |
| RSS-05 · P0 | 已读、未读、收藏、加入稍后阅读、批量标已读 | 批量操作确认当前源/筛选范围，不误处理隐藏内容 |
| RSS-06 · P0 | OPML 导入/导出、逐源暂停/恢复/删除 | 导入结果显示新增/重复/失败；OPML 不宣称包含正文和进度 |
| RSS-07 · P0 | 处理 304、超时、429、鉴权和地址变更 | 304 视为成功无更新；429 按服务端提示退避 |

### 10.3 全文与下载策略

首次添加建议保存最近 50 条元信息；默认在 Wi-Fi 下自动获取每源最近 20 条新条目的正文及必要图片。常规刷新同样优先新条目；全局每轮最多 60 篇，待处理项保持队列，不静默丢弃。以上均为可调整的初始策略，R0 后校准。

移动网络下手动刷新默认更新 Feed 和其中已有的正文文字，不自动批量获取外部全文或图片。用户点开未保存文章或主动“下载全文”时，告知需联网并允许本次下载；已经完整保存的文章不重新联网。设置可按源改为“只保存 Feed 内容”或关闭全文自动获取。

首次同步不自动抓取整个历史库。视频、音频等非首版离线对象同稍后阅读处理；全文不可获取时仍保留摘要与原文链接。

### 10.4 刷新调度与条目一致性

建议后台刷新间隔提供 1、3、6、12、24 小时和关闭，默认 6 小时、仅 Wi-Fi。界面描述为“约每 6 小时检查”，不承诺精确闹钟。Android WorkManager 周期任务受到系统调度、约束和节电机制影响，不能等同准点执行。[S9]

唯一条目优先使用“订阅源 ID + GUID/Atom ID”；缺失时回退规范化原文 URL，再回退稳定字段组合。Feed 内 GUID 与跨源文章身份分开，不能全局只按 GUID 判重。同 URL 的文章更新应产生内容版本，不新增重复未读条目。

清除缓存后保留必要条目身份与已读记录；用户删除的条目保留删除标记，建议 180 天，用于避免刷新立即重新出现。Feed 条目从源中消失不等于用户主动保存的快照也应删除。

## 11 保存状态、离线与存储生命周期

### 11.1 状态必须分轴，不混成一个字段

| 状态轴 | 建议值 | 业务含义 |
| --- | --- | --- |
| 获取任务 | 排队、等待网络、获取中、解析中、资源下载中、需用户操作、完成、失败、取消 | 描述处理过程；与已有快照状态独立 |
| 正文质量 | 未获取、摘要、部分正文、完整性未确认、完整正文 | 描述正文完整程度及其判断依据 |
| 本地资源 | 仅链接、正文可离线、部分图片离线、正文及必要图片离线 | 描述资源是否在本机；不能反推正文就是全文 |
| 阅读管理 | 未读/阅读中/已读；收藏开关；归档开关；稍后阅读关联 | 描述用户管理意图，与抓取成功失败无关 |

### 11.2 面向用户的合成文案

“完整图文离线”仅在正文质量为完整、当前快照已提交、必要图片均已保存或被用户明确排除时出现。详情同时说明“视频/音频等需查看原文”。无图片的完整正文可以满足此状态，不需要为零张图片保留下载任务。

正文已存但图片缺失显示“文字已离线，缺 X 张图片”；仅抓到摘要显示“摘要已保存”；不确定正文完整性显示“已保存，全文完整性未确认”；已有旧版而更新失败显示“旧版可离线，更新失败”。用户可以继续读旧版，不被错误页面挡住。

取消新任务不会清空旧快照；失败任务不会重置阅读状态；网络恢复只重试仍有效的任务。后台到达“需用户操作”后暂停，禁止循环弹登录窗口。

### 11.3 持久内容与可清理缓存

**持久内容：** 导入的图书副本；用户主动保存/收藏的文章正文与资源；仍被这些内容引用的资源；阅读进度、书签、分类、订阅与管理状态。禁止自动清理。

**可清理缓存：** 缩略图、可重建分页索引、临时文件、用户未主动保留的 RSS 文章下载缓存。RSS 缓存被清理后须立刻降级离线标识，保留条目、原文链接和已读状态。

建议可清理 RSS 资源缓存上限 1 GB，已读且超过 30 天的未保留内容优先淘汰。未读超限时提示选择，不为凑限额清空用户待读；空间紧张时先暂停新下载。用户主动保存的文章不受该上限自动淘汰。

### 11.4 删除规则

删除书籍、移出稍后阅读、删除订阅和清理缓存是不同操作。删除订阅默认停止更新并移除源关系，明确询问是否清理未保留条目；已经收藏、加入稍后阅读或有其他来源引用的文章继续保留。

资源采用引用关系回收：正文仍被任何内容实体、保留版本或备份任务使用时不删除。删除正在下载的条目先取消任务，再清理临时文件，防止已删除内容被任务重新写回。

## 12 数据模型、备份与设置

### 12.1 逻辑数据对象

以下为产品级数据契约，不限定实际数据库表名。书籍和文章可以共享上层内容实体，但必须保留各自字段，不能为追求统一而丢失来源与格式语义。

| 对象 | 必备信息 | 关键关系与约束 |
| --- | --- | --- |
| Book | ID、标题、作者、格式、文件指纹、文件位置、封面、大小、导入时间 | 原文件只读；关联分类、进度和书签 |
| Article | ID、规范身份、原始/最终 URL、标题、作者、来源、各类时间、保留意图 | 可同时关联多个来源、稍后阅读和收藏 |
| ArticleSnapshot | 版本、正文位置、正文质量、判定依据、提取规则版本、创建时间 | 当前版本原子切换；旧版有效内容不得被失败结果覆盖 |
| Asset | ID、原 URL、类型、尺寸、指纹、本地位置、下载状态 | 与快照多对多引用；按引用回收 |
| Feed / FeedItem | 源 URL、分组、策略、ETag/更新时间；条目 GUID、发现时间 | 条目身份限定源作用域；关联 Article |
| ReadingPosition | 内容 ID、版本、当前/最远位置、锚点类型、最后阅读时间 | 不把可变屏幕页码作为流式内容唯一定位 |
| Bookmark | 内容 ID、快照版本、锚点、摘要、创建时间 | 书籍/文章变更后允许备用定位和失效提示 |
| CaptureTask | 目标 ID、阶段、重试次数、错误码、资源进度、取消标记 | 可恢复、幂等；不得复活已删除内容 |

### 12.2 URL 与时间处理

原始 URL 用于溯源，规范 URL 用于判重；追踪参数仅在明确不影响内容身份时删除。知乎回答 ID、文章 ID、有效查询参数、哈希路由不得盲目清除。公众号分享地址中的内容标识不能因为“去参数”被误合并。

发布时间保留来源原值和解析后的时区时间；没有发布时间则为空，不以抓取时间伪造。UTC 时间用于内部一致性，界面按设备时区展示。用户改时区不应改变文章身份或已读状态。

### 12.3 手动备份与恢复

**DATA-01 · P0：** 提供“完整备份”和“仅配置与记录”。完整备份包含图书副本、主动保留的文章及其资源、订阅、分类、设置、进度和书签；普通 RSS 可清理缓存默认不含，界面明确列出范围。仅配置与记录不包含正文和书籍，不宣传为可直接离线阅读的完整恢复。

**DATA-02 · P0：** 备份包包含格式版本、清单、文件校验值、生成时间和范围说明。导出前估算大小与空间。首版备份包默认不加密，导出前显著提示可能含私人阅读内容；Cookie、令牌与登录会话始终排除。

**DATA-03 · P0：** 首版完整恢复采用“校验 → 预览 → 确认替换本地库 → 恢复”，不提供不可靠的自动合并。替换前要求确认现有数据处置，并提供先备份入口；数据恢复在暂存区校验成功后整体切换，失败保留原库。

**DATA-04 · P0：** 高于应用可识别的备份版本拒绝恢复并说明；低版本按已实现迁移处理。导入缺失文件的元数据备份时显示“待重新关联文件”，不得显示为正常可读。数据管理页提示“卸载前请先导出备份”，不拦截系统卸载；已导出的备份包不随应用内删除自动消失。

### 12.4 设置分组

阅读设置包括全局主题、图书/文章默认版式和字体管理；网络设置包括 RSS 周期、Wi-Fi 限制与逐源全文策略；数据设置包括存储占用、缓存清理、备份恢复；隐私设置包括站点会话清理与诊断日志；关于包括版本、开源许可与已知兼容范围。

## 13 技术原则与开源参考

### 13.1 推荐结构，最终由 R0 决策

应用层建议使用 Kotlin/Jetpack Compose；业务逻辑分为书架、订阅、文章获取、资源下载、阅读状态和数据管理。流式阅读内核优先验证 foliate-js，Readium Kotlin Toolkit 作为对照；PDF 和漫画单独选择后端。

本地文章优先保存为“清洗后的 HTML + 本地资源 + 元信息”，通过适配层送入阅读器；不要求所有文章入库时都转换为 EPUB。图书保留原文件，解析结果作为可重建数据。数据库、资源文件和后台任务通过内容 ID 关联，不让 UI 直接依赖某个阅读引擎的私有对象。

Android 官方文档支持使用 WebViewAssetLoader 加载应用内 HTML/CSS/JavaScript 等资源；这一能力可用于本地正文渲染，不代表需要在线网页作为阅读页面。[S8]

所有直接复制、修改或引入的代码记录来源、版本/提交、许可证、修改范围和升级路径；参考交互但自行实现，与直接复制代码分开登记。未决定整体发布许可前，不先拼接多个应用再事后补授权。

阅读内核、解压库、PDF 后端、字体、图片组件与 JS 安全清洗组件都要建立依赖清单。只使用可复现的锁定版本，升级先跑回归样本；禁止生产构建自动拉取不受控的最新分支。许可证兼容性与发布义务需在分发前专项审查，本文不作法律结论。

## 14 隐私、安全与权限

### 14.1 网络与本地阅读隔离

**SEC-01 · P0：** 用于登录/获取真实网站的交互 WebView，与用于本地阅读的可信容器隔离；前者不暴露应用文件、数据库和通用原生桥。Android 官方指出，不可信内容与 WebView 原生桥结合可能扩大安全风险，需限定暴露范围与可信来源。[S11]

**SEC-02 · P0：** 禁止书籍和文章自带的任意脚本、事件处理器、危险链接与跟踪资源执行；阅读引擎自身的可信脚本可在限制环境运行。采用内容安全策略、HTML/CSS 清洗和受限资源加载，不以“全部关闭 JavaScript”破坏引擎工作，也不以“同源”误认所有内容可信。[S2、S3]

**SEC-03 · P0：** 本地阅读页面默认禁止远程请求。需要打开外链或加载明确不在离线范围的内容时，由用户操作跳转并提示联网。不能因缺图悄悄回源，使“离线阅读”变成隐式跟踪。

**SEC-04 · P0：** URL 抓取限制协议、跳转次数、响应大小与超时；拒绝危险 URI、默认拒绝内网/回环目标，重定向后重新校验。仅接受 HTTPS；确需 HTTP 的订阅源须逐源告知风险并显式允许，不全局降级。

### 14.2 文件与资源安全

**SEC-05 · P0：** EPUB/漫画/备份解包需防路径穿越、异常层级、压缩炸弹和资源数量失控；所有输出路径限制在本任务目录。SVG、HTML 和 CSS 中的外部资源同样检查，不只过滤 script 标签。

**SEC-06 · P0：** 图片与 PDF 采用有限并发、尺寸限制、按需渲染和内存回收；单个异常文件不拖垮批量任务。内核和解析器安全更新纳入维护。

### 14.3 权限与隐私

默认只请求必要网络能力；文件访问通过系统选择器授权。[S10] 不要求通讯录、定位、无障碍服务、读取其他应用数据或全文件管理权限。通知为增强项，用户拒绝也能完成核心流程。

默认无远程行为分析和正文上传。诊断日志以本地记录为主，只含任务阶段、错误分类和性能信息；用户主动导出前提示内容与敏感信息范围。URL 查询参数、正文、账号、Cookie、书名和阅读历史不得直接进入默认诊断日志。

应用私有数据和站点凭证的系统备份/设备迁移策略必须显式配置，并在目标系统上验证。首版本地优先方案默认不把书库和会话加入自动云备份；本地手动导出由用户明确发起。

## 15 非功能要求与异常处理

### 15.1 性能和稳定性目标

下表为建议门槛，非实测数据。验收设备为现有测试手机（记录具体型号、系统和 WebView 版本），另需最低支持版本（API 29）真机或模拟器。计时使用 Release 包，至少 30 次采样计算 P95；首次导入/建索引与再次打开分开报告。

| 指标 | 拟定目标 | 测量条件 |
| --- | --- | --- |
| 应用冷启动至主列表可交互 | P95 ≤2 秒 | 已有 1,000 本书和 10,000 条文章元信息；不等待网络 |
| 已入库普通流式书首屏 | P95 ≤3 秒 | ≤20 MB 的标准样本；首次导入解析另计 |
| 已保存文章首屏 | P95 ≤1 秒 | 正文 ≤200 KB、必要资源已在本机 |
| 普通分页操作反馈 | P95 ≤200 毫秒 | 字体/章节已加载；跨章节单独记录 |
| 已导入 PDF/漫画首屏 | P95 ≤3 秒 | 标准性能样本 ≤100 MB；复杂样本另列 |
| 压力测试 | 连续阅读 60 分钟无崩溃、无持续内存增长 | 混合切换内容、缩放、旋转和切后台 |
| 数据可靠性 | 事务、定位、备份用例 100% 通过 | 强杀、磁盘不足、升级迁移和失败恢复 |

大型文件另设压力组：TXT 至少 20 MB，PDF 至少 500 MB，漫画至少 500 MB 或 500 张图片。压力组不承诺与普通组相同时延，但要有可取消的加载反馈、可说明的失败和内存保护。尺寸/解包限额应配置化，超限明确提示。

### 15.2 异常文案与动作

| 场景 | 用户文案示例 | 允许操作与恢复规则 |
| --- | --- | --- |
| 离线新增链接 | 链接已保存，等待联网获取正文 | 查看任务、取消；联网后按策略继续 |
| 仅取得摘要 | 已保存摘要，暂未取得全文 | 读摘要、打开原文、尝试重新获取 |
| 图片部分失败 | 文字已离线，3 张图片尚未保存 | 读正文、仅重试失败图片 |
| 登录/验证 | 需要在网站中完成登录或验证 | 打开交互页面；不自动填写凭证 |
| 文章删除/不可访问 | 原文暂不可访问，已保留链接 | 重试；有旧版则优先提供旧版阅读 |
| 更新失败 | 更新失败，原有离线版本未受影响 | 继续读旧版、重新获取 |
| RSS 限流 | 来源暂时限制请求，稍后自动重试 | 展示预计重试条件，不持续刷接口 |
| 磁盘不足 | 空间不足，已暂停下载 | 清理可重建缓存、取消；不删持久内容 |
| 损坏图书/图片 | 此文件或页面无法解析 | 换文件、重试、跳过；批量任务继续 |
| WebView 不兼容 | 当前系统阅读组件无法运行此内容 | 显示诊断信息与更新指引；不白屏无反馈 |

### 15.3 无障碍与适配

所有主要触控目标建议不小于 48dp；支持系统字体缩放后主要按钮与列表不截断。TalkBack 能读出导航、状态和操作名称，正文阅读顺序正确；在 R0 单独验证嵌入式阅读器的可访问性，不因使用 Compose 就默认全应用通过。

手机竖屏、横屏、平板与折叠屏布局均不遮挡正文与安全区，布局规则见 4.5；折叠屏需验证展开/折叠切换时阅读位置不变。浅色/深色主题均检查文字对比度；图片不默认强制反色。应用界面（非阅读页）深色主题的设计暂缓，阅读页夜间模式已有设计。高刷和电子墨水专项优化为后续增强。

## 16 验收样本、用例与质量门槛

### 16.1 样本库

样本应来自合法自有、授权或开放内容，不把受限制内容解锁作为测试任务。每个样本记录文件/链接、内容类型、特征、预期正文与资源、日期、设备、引擎版本和结果；网页同时保留可用于规则回归的合规页面样本。

| 样本组 | 最小建议规模 | 必须覆盖 |
| --- | --- | --- |
| EPUB | 30 本 | 流式 20、固定版式 10；中文/英文、图片、脚注、表格、代码、嵌入字体 |
| MOBI | 15 本 | 旧 MOBI、混合 MOBI、图片/目录、较大文件；均无 DRM |
| TXT | 15 份 | UTF-8/UTF-16/GB18030、有/无目录、长段落、超长文件 |
| PDF | 20 份 | 扫描、文字、混合页、双栏、旋转、不同页面尺寸 |
| 漫画 | 20 册 | CBZ/ZIP 15、图片目录 5；自然排序、长图、超大图、左右方向 |
| 异常本地文件 | 15 份 | 损坏、加密、伪扩展名、重复、压缩异常、缺图和空间不足 |
| 目标站点公开页面 | 50 篇 | 公众号 20、知乎专栏 15、知乎单回答 15；不同作者与版式 |
| 通用文章/新闻网页 | 40 篇 | 普通长文 20、新闻正文 20；图片、代码、表格、摘要 |
| 访问受限/异常网页 | 20 篇 | 登录、验证、删除、跳转、仅摘要、资源失效；单独计数 |
| 订阅源 | 12 个及测试 Feed | RSS 8、Atom 4；全文/摘要、重复 GUID、缺失字段和更新 |

网页指标必须分别报告“自动完整保存率”“用户辅助后的完整保存率”“正确降级率”。公开可访问且符合首版范围的页面作为完整保存率分母；受限样本单独统计，不偷偷从报告中消失，也不混入分母夸大或压低能力。

### 16.2 核心验收用例

| 用例编号 | 场景与步骤 | 通过标准 |
| --- | --- | --- |
| AT-01 | 批量导入 EPUB/MOBI/TXT/PDF/漫画与一个损坏文件 | 有效文件可读；坏文件单独失败；数量与状态正确 |
| AT-02 | 同文件改名后再次导入；同名不同内容分别导入 | 前者去重且保留位置；后者允许并存 |
| AT-03 | 导入后删除外部原文件，断网重启应用 | 应用副本仍可读；目录与图片正常 |
| AT-04 | 同一本书改字体、字号、边距、主题并旋转 | 无缺段重段；恢复至同一文本锚点或同段附近 |
| AT-05 | 阅读途中切后台、强杀、重启和重新打开 | 恢复至最近已提交位置；书签不丢失 |
| AT-06 | PDF 放大拖动、跳页、书签；漫画 RTL 与长图阅读 | 无手势冲突；重新打开位置与方向正确 |
| AT-07 | 从微信/知乎分享包含标题的链接；离线再次保存 | 链接立即入列；有网完成处理；离线任务等待且不重复 |
| AT-08 | 对目标站点样本保存，开启飞行模式查看全文 | 必要段落/图片完整；摘要或缺图不能显示完整离线 |
| AT-09 | 登录受限、删除或风控页面 | 提示真实原因；无伪正文、无无限重试或绕过流程 |
| AT-10 | 有离线旧版时强制模拟重新抓取失败 | 旧版仍可阅读；位置、已读、归档和收藏不变 |
| AT-11 | 添加 RSS/Atom，分别遇到正文、摘要和重复条目 | 正文链路正确；摘要标识清楚；已读不因刷新丢失 |
| AT-12 | 同文章先通过 RSS 保存，再通过分享保存 | 关联同一内容；不重复下载；管理状态一致 |
| AT-13 | 清理缓存、删除订阅、移出稍后阅读 | 持久内容不误删；引用资源不误回收；离线状态及时改变 |
| AT-14 | 完整备份后清空测试库并恢复；模拟备份损坏 | 正常包恢复记录与校验一致；坏包不破坏现有库 |
| AT-15 | 含脚本/外部资源 EPUB、恶意 HTML、路径穿越压缩包 | 无脚本越权、远程偷跑或目录越界；应用可继续使用 |
| AT-16 | 节电/无网后重新进入 RSS，触发手动刷新 | 展示真实更新时间；手动可恢复；不承诺后台准点 |

### 16.3 发布阻断项

任何用户数据误删、成功保存却缺失关键正文、跨内容定位到错书、离线状态虚假、脚本越权、备份破坏原库，均为发布阻断。崩溃/无响应、核心格式打不开、主要站点流程无法完成等按影响范围评估，不用平均指标抵消。

所有 P0 功能和核心用例通过、兼容样本达标、安全检查通过、依赖清单完成，才进入 R1 发布。允许的已知限制必须在兼容说明和相关操作入口中一致出现。

### 16.4 产品指标与诊断

首版以本地测试、用户主动反馈和可选择导出的诊断为主，不设默认远程埋点。可记录的非内容指标包括：导入成功/失败分类、打开耗时、抓取阶段、正文质量、缺图数量、RSS 刷新结果和恢复结果。

“完整保存率 = 完整正文且必要资源保存成功的合格样本数 / 合格样本总数”；“辅助完成率”另外统计。网页抓取前后的内容质量与资源状态分开记录，避免把网络成功率误当正文成功率。

### 17.2 R0 必须回答的问题

**排版。** 候选内核在 Android WebView 上能否满足中文排版、脚注、选词、固定版式及定位？如果 foliate-js 不满足，备用方案如何继续保留 MOBI，而不是取消用户要求？

**网站。** 目标页面能自动获取到什么程度，哪些必须用户交互，哪些只能保留链接？正文与必要图片是否真的能断网阅读？

**资源。** PDF、MOBI 解压和漫画大图在目标设备上是否有内存风险？应用最低系统与 WebView 版本是什么？

**数据。** 引擎升级或正文重抓后锚点如何迁移？本地备份能否不依赖账号而完整恢复主动保留的内容？

### 17.3 各角色交付物

产品交付范围矩阵、状态/异常规则和评审决议；设计交付页面流、阅读设置、保存状态、空/错/加载态与无障碍标注；开发交付接口边界、数据迁移方案、样本自动化、依赖清单与构建说明；测试交付兼容库、核心用例、性能记录和发布报告。
