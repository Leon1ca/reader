## 2. 本次必须实际完成的首个增量 I0

**目标：用户可以把自己的 TXT 文件复制进本地书库、阅读、加书签，并在退出或重启后继续阅读。**

**2026-10-04 用户补充优先：正文排版必须与已安装的 Readest 一致，包括文章默认中英文、数字字体。最简 Material3 仅指外围界面，不降低正文要求。早期 Compose TXT 已完成数据闭环过渡，I0 受控 WebView TXT 与固定字体已接入并完成基础构建/设备测试，仍未通过严格正文对照；进入正式流式阅读前按 [READEST_PARITY.md](READEST_PARITY.md) 完成固定版本字体、CSS、内核与同设备对照。** 这是本地数据与阅读位置的第一条完整纵向流程，不等于 R0 全部验证完成，更不等于 R1 已完成。

### I0 交付要求

1. 原生 Compose 书架、阅读器和基础设置，按用户要求使用临时最简 Material3 功能界面，提供中文空状态/错误状态；不投入高保真、皮肤或视觉资产。保持业务与 UI 分离，后续按用户提供的界面设计替换。构建产出 Debug APK，附复现命令与兼容说明。
2. SAF 单/多文件选择；逐项 TXT 导入结果；检查可读性、字节数和内容类型，拒绝明显二进制及当前未支持格式。扩展名和 MIME 都只能作为线索。取消文件选择不报错。
3. 应用私有目录复制入库；流式计算 SHA-256；改名同文件返回已有书目、保留进度/书签；同名异内容允许并存；绝不删除外部原文件。
4. 暂存→解析/建索引→正式提交；只有文件及索引有效后才显示为可读。进程中断后清理未完成暂存/孤儿文件；重复导入和并发导入不能产生重复实体。剩余空间不足时明示错误，不清理用户内容。
5. UTF-8、带 BOM 的 UTF-16LE/BE；提供 GB18030 手动指定/重试入口和可理解的编码错误。保留原始字节副本。编码不确定时不无提示用替换符吞掉正文。
6. 稳定段落/文本偏移与分段索引；章节标题识别失败允许固定大小分段并标为“分段”，不伪称原书目录。限制单段与单次加载的大小；20 MB 压力样本不能一次性渲染整个文件。
7. 滚动阅读、分段导航、字号与浅色/深色/纸色设置；改变字号或旋转后恢复同一内容段落。先不把滚动列表冒称完整分页阅读。
8. 当前位置、最远位置分开存储；位置带内容 ID、索引版本、段落/字符偏移与备用比例；稳定阅读位置约 1 秒内提交，退出/切后台立即提交。书签添加、删除、列表跳转及重启恢复。
9. 书架标题搜索、最近阅读/导入时间/标题排序；删除应用内副本与该书记录前确认；坏文件不阻塞其他导入项。
10. 不申请全文件访问权限；本地阅读不需要联网；禁止默认系统云备份包含书库或会话。若后台网络功能尚未接入，首增量无需 INTERNET 权限。
11. 未实现格式与稍后阅读/RSS 在说明中明确列出。界面可保留主导航的“开发中”页，但不能用可点击的伪操作或示例数据暗示功能已完成。

### I0 范围边界

本次不宣称支持 EPUB/MOBI/PDF/漫画，不宣称 Readest 排版已对齐，不宣称网页或 RSS 已可离线。完整 TXT P0 中的横向分页、导入字体、全部版式设置、规则预览/重新分章迁移等仍需后续完成。其余格式和站点没有从 R1 删除。

若编码阶段在不削弱数据可靠性与测试的前提下有余量，可以加入分类；不要为了增加格式数量而加入只能展示纯文本的“PDF 支持”。

## 3. 首增量技术结构

先用一个 Android app 模块，按职责分包；复杂业务稳定后再拆 Gradle 模块，避免空模块堆砌。

- `domain`：Book、ReadingPosition、Bookmark、ReadingPreferences、格式化错误以及 `Locator`。数据模型不依赖 Compose/WebView/foliate 类型。
- `data`：数据库、私有文件仓库、导入提交与清理、事务、设置。UI 只调用 repository/use case。
- `reader`：`ReaderEngine`/session 边界。输入是内容 ID、受控本地资源、位置和偏好；输出是位置事件、目录、可用能力、明确错误。
- `txt`：解码、章节/段落索引、按段加载；早期 Compose 文本已由受控 WebView/CSS 有界 TXT 载体接替，I0 基础构建/设备结果见 VALIDATION.md；真正分页器集成按 CORE_ARCHITECTURE.md 的阶段关口执行。正文规则与 backend 分离，固定候选以源码与运行证据选择；导入索引和持久化保持独立。
- `ui`：书架、导入状态、阅读器、书签、设置；ViewModel/Flow 提供状态，耗时 I/O 不在主线程执行。

### 数据正确性优先

数据库优先 Room，导出 schema 并禁止破坏式迁移；若为避免初次 KSP 配置引入平台 SQLiteOpenHelper，则统一封装 repository、明确 schema version 与升级路径，不把 SQL 混入 UI。之后改 Room 不得重建用户书库。

文件系统和数据库不是同一事务：先在同一文件系统暂存完整文件/索引并校验，再原子重命名，最后提交数据库；启动时对孤儿文件和未提交任务做幂等恢复。删除先标记/取消相关工作，再清理引用与文件，重入不复活已删除书籍。

`Locator` 应按格式区分：TXT 段落/字符偏移，EPUB/MOBI 资源/文本锚点（可附 CFI），PDF 原始页号/标准化坐标，漫画图片 ID/逻辑序号/页内位置。屏幕像素、当前页码或百分比都不能是流式正文的唯一位置。

## 6. 风险关口和具体处理

### 阅读内核关口

foliate-js 上游公开支持 MOBI/KF8；旧 MOBI 文本可能一次解压，PDF 适配仍属高度实验性。因此作为流式候选，不把其 PDF 适配设为默认生产后端；针对大 MOBI 做内存验证，并对冻结 commit 做源码审查。[上游说明](https://github.com/johnfactotum/foliate-js)

Readium 上游列出 EPUB/PDF 和部分 CBZ 能力，当前表中未列 MOBI；若选择 Readium，仍需专门保留 MOBI 路线。不要把上游 develop 的依赖要求直接套入本项目，也不要把同名格式支持等同本项目验收通过。[上游格式和构建矩阵](https://github.com/readium/kotlin-toolkit)

PDF 先验证平台 PdfRenderer 作为独立后端，按页按需渲染、关闭页面/文件句柄、限制缓存；在所选 minSdk 上确认可用 API，不使用较新 API 而无版本保护。[Android PdfRenderer](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer)

### WebView 关口

本地阅读容器和带账号的网站获取容器隔离。受控加载、CSP、HTML/CSS/URL 清洗、禁止书内脚本/事件处理器、禁远程隐式回源是独立要求；引擎的可信脚本与内容脚本分开。任何需要原生桥的方案都必须限定来源和可调用能力，不能将通用文件/数据库接口暴露给文档。先恶意样本验证，再引入真实用户内容。

### 存储与备份关口

导入去重不能重置状态；重抓失败不覆盖旧快照；清缓存不清持久内容。备份在临时库中校验清单/校验值/路径后整体切换，失败保留原库。加密未实现前明确说明范围；Cookie/令牌从不进备份。任何误删、错书定位、伪离线和破坏现有库的恢复都阻断交付。

### 网络和资源关口

抓取拒绝危险协议/回环/内网；每次重定向重新验证；超时、字节数、跳转数、图片像素/并发有限额。压缩包限制输出目录、路径、总大小、文件数和压缩比。网页正文质量、任务状态、离线资源、阅读管理状态分别持久化，最终文案才合成；禁止把 HTTP 200 或高字数当“全文已保存”。

## 7. I0 验证与独立审核交付

### 自动化优先覆盖业务不变量

- 编码：UTF-8/UTF-16LE/BE/GB18030，换行变体、空文件、二进制伪装、中文章节、超长段落；无正文静默截断。
- 导入：同字节改名去重、同名不同字节并存、一次坏文件不阻断批量、取消、超限、失败清理、数据库唯一约束。
- 位置：前进/回翻保留当前位置与最远位置，改变字号后段落锚点不变，书签去重/删除，索引版本不匹配有明确降级。
- 持久化：重开数据库保持书目/偏好/进度/书签；事务失败不产生可读半成品；删除只影响目标内容。

运行构建、单元测试和 Android lint。若有可用模拟器/真机，至少运行导入→读到中段→书签→改字号/旋转→后台/强杀→重开→移除外部原件→离线阅读→删除内副本流程。若缺少设备，明确区分“编译通过”“单元测试通过”“未做设备验证”，不将编译成功描述为运行验证。

独立审核角色应读取 PRD、本计划、实现及测试结果，聚焦文件/事务可靠性、位置串书/回退、生命周期竞态、权限备份泄露、全量文本内存，以及范围宣传。报告需提供问题严重度、触发条件、文件位置、建议修复和剩余限制；编码角色修复后复核。不得由编码角色自行宣称独立审核完成。

交付至少包括源码、固定构建入口、APK（构建成功时）、构建/测试记录、已实现与未实现范围、依赖清单和独立审核记录。PRD 的 ≥95%/≥90%/P95 目标只有完成规定样本与测量后才能报告为达标。
